PROYECTOS DE SISTEMAS EMBEBIDOS

Diseño de Sistemas Embebidos e IoT sobre Raspberry Pi 4

Esta sección engloba el desarrollo práctico de la asignatura dividido en dos proyectos consecutivos e interconectados:

- El Proyecto II, centrado en la creación de un sistema Linux embebido a medida con Buildroot y la comunicación I2C con sensores.

- El Proyecto III, enfocado en la construcción de una arquitectura distribuida IoT con sockets UDP, telemetría MQTT y visualización gráfica en ThingsBoard.

Plataforma hardware: Raspberry Pi 4 Model B, acelerómetro MPU6050 y sensor de color TCS34725.

Proyecto II: Sistema Linux Embebido con Buildroot y Sensores I2C

El objetivo principal de este proyecto fue la generación de una distribución Linux reducida y adaptada (custom Linux) mediante Buildroot para la plataforma Raspberry Pi 4. Sobre esta imagen se configuró la compilación cruzada (cross-compilation) y se desarrolló un programa ejecutable en C para la lectura e interacción simultánea con dos sensores sobre el bus hardware I2C.

Especificaciones Técnicas y Plataforma

  • Plataforma Target: Raspberry Pi 4 Model B
  • Generador de Sistema Operativo: Buildroot (Toolchain, Linux Kernel, BusyBox)
  • Entorno de Desarrollo: VSCode con Toolchain de compilación cruzada ARM y depuración SSH
  • Protocolo de Comunicación: Bus I2C en Linux (/dev/i2c-1)
  • Sensores Integrados: Acelerómetro/Giroscopio MPU6050 (0x68) y Sensor de Color RGBC TCS34725 (0x29)

Arquitectura y Fases de Desarrollo

01 — Configuración y Personalización de Buildroot

Selección del objetivo Raspberry Pi 4, integración del firmware de Broadcom para la tarjeta de red inalámbrica (BCM43438) y edición de scripts de post-construcción (post-build.sh) para autoconfigurar wpa_supplicant.conf y permitir acceso SSH como root.

02 — Modificación del Kernel de Linux

Habilitación de los drivers del controlador I2C de Broadcom (BCM2835/BCM2708) mediante make linux-menuconfig para activar el soporte de dispositivos I2C en el espacio de usuario.

03 — Entorno de Cross-Compilation en VSCode

Integración de la toolchain generada por Buildroot mediante archivos de tareas (tasks.json, launch.json) para compilar en el PC host y transferir los binarios ejecutables ARM automáticamente a la RPi4.

04 — Controlador de Sensores I2C en C

Implementación de lecturas utilizando la API ioctl() con I2C_SLAVE: inicialización del MPU6050 para lectura continua de aceleración en 3 ejes, y configuración del TCS34725 ajustando registros de ganancia y tiempos de integración para la extracción de componentes RGBC.

Proyecto III: Aplicación IoT Cliente-Servidor UDP y Dashboard ThingsBoard

Diseño e implementación de un sistema IoT extremo a extremo (End-to-End). La Raspberry Pi actúa como nodo cliente leyendo los datos muestreados por los sensores I2C y enviándolos mediante sockets UDP a un servidor central en C desplegado en Ubuntu para su análisis estadístico. En paralelo, la información se retransmite sobre MQTT a la plataforma ThingsBoard.

Especificaciones Técnicas y Plataforma

  • Nodo Cliente Embebido: Raspberry Pi 4 con Linux Buildroot y script de autostart (init.d)[cite: 6]
  • Servidor de Datos: Máquina Linux Ubuntu ejecutando la aplicación receptora en C
  • Red y Transporte: Sockets UDP IPv4 para la comunicación Cliente-Servidor
  • Protocolo IoT: MQTT mediante cliente mosquitto_pub enviando payloads en formato JSON
  • Plataforma Dashboard: ThingsBoard desplegado con base de datos PostgreSQL

Arquitectura y Módulos

01 — Cliente UDP (IOTClient.c)

Programa en C que se ejecuta automáticamente al arrancar la Raspberry Pi[cite: 6]. Realiza el handshake ("Hello Server" / "Hello RPI"), muestrea los datos de los sensores I2C y empaqueta las lecturas para envío UDP.

02 — Servidor Estadístico UDP (IOTServer.c)

Servidor en C que escucha peticiones en un puerto socket dedicado, recibe ráfagas de datos, parsea las muestras y genera cálculos estadísticos en tiempo real (media, máximo, mínimo, desviación típica) sobre la aceleración y componentes de color.

03 — Agente de Telemetría MQTT

Integración del cliente Mosquitto dentro de la imagen de Buildroot para publicar métricas de telemetría hacia ThingsBoard en el tópico v1/devices/me/telemetry mediante credenciales de token.

04 — Panel de Control ThingsBoard

Configuración de widgets interactivos: gráficos de series temporales para niveles de iluminación/color y gráfico polar/radar para representar el vector de aceleración espacial 3D en tiempo real[cite: 6].
